# 无人系统意图协同平台原型功能完善说明

## 1. 项目总体定位

本项目面向无人车、无人机、路侧设备 RSU、应急车辆和广域通信链路等异构无人系统，目标是通过统一意图表达、DSL 任务描述、IDL 数据建模、DDS 发布订阅通信、QoS 策略、多设备协同调度、路径规划和状态反馈，形成可解释、可演示、可扩展的无人系统意图协同平台原型。

本次完善将原先“输入自然语言并返回演示结果”的单点流程，扩展为“意图解析 -> 结构化 DSL -> IDL/DDS/QoS -> 路径规划 -> 设备调度 -> DDS 通信模拟 -> 风险与降级反馈”的闭环流程。

## 2. 当前项目原有不足

- 意图识别偏演示化，主要围绕乘客路线协同，任务类型覆盖不足。
- DSL 输出以字符串为主，缺少可直接用于业务编排的结构化字段。
- DDS Topic 与 QoS 多为静态展示，缺少按任务紧急程度和通信场景动态选择的逻辑。
- 设备模型字段较少，无法表达能力、电量、负载、链路质量、位置和支持 Topic。
- 路径规划已有 A* 动态边权算法，但候选路径、风险说明和不推荐原因展示不足。
- 后端 API 主要服务前端工作台，缺少平台级设备、Topic、日志、模拟和健康接口。
- 前端页面有协同闭环展示，但缺少完整平台计划、结构化 DSL、QoS、分工、日志和降级策略的可读展示。

## 3. 核心增强内容

### 3.1 平台级编排器

新增 `agent.PlatformOrchestrator`，负责生成完整协同计划：

1. 解析自然语言任务意图；
2. 识别任务类型、起点、终点、紧急程度、参与设备、安全偏好、可靠性要求、时间限制和风险因素；
3. 生成结构化 DSL；
4. 生成 IDL 绑定；
5. 选择 DDS Topic；
6. 按任务紧急程度和通信场景选择 QoS；
7. 调用路径规划算法；
8. 调用多设备任务调度算法；
9. 模拟 DDS 发布、订阅、失败、重试和降级；
10. 返回执行状态、风险提示和降级策略。

### 3.2 增强任务类型

当前支持的任务类型包括：

- 应急救援
- 医疗转运
- 交通疏导
- 无人机巡检
- 事故检测
- 物资配送
- 广域态势感知
- 多设备联合巡逻

当输入信息不完整时，系统使用默认值并在 `defaultHints` 和 `riskWarnings` 中返回提示，避免流程失败。

### 3.3 结构化 DSL

新增结构化 DSL 输出字段：

- `dslVersion`
- `missionId`
- `task`
- `source`
- `target`
- `devices`
- `priority`
- `qos`
- `constraints`
- `expectedOutput`
- `missingInfoHints`

该结构可直接用于后续 DSL 文件生成、IDL 绑定或可视化展示。

### 3.4 DDS Topic 与 QoS

新增平台级 Topic 目录：

- `VehicleStatusTopic`
- `DroneMissionTopic`
- `EmergencyDispatchTopic`
- `RoadSideUnitTopic`
- `TrafficRiskTopic`
- `CollaborationPlanTopic`

QoS 动态选择字段：

- `reliability`
- `durability`
- `deadlineMs`
- `latencyBudgetMs`
- `historyDepth`
- `priority`
- `reason`

应急、医疗、协同计划等关键任务使用 `RELIABLE + TRANSIENT_LOCAL`，传感器态势类数据可使用 `BEST_EFFORT + VOLATILE` 以降低链路压力。

### 3.5 多设备协同模型

平台级设备模型包含：

- `deviceId`
- `deviceType`
- `capabilities`
- `batteryLevel`
- `currentLoad`
- `linkQuality`
- `location`
- `status`
- `supportedTopics`

调度结果包含任务、设备、评分和分配原因。调度算法为“基于动态权重评分的贪心任务调度算法”，综合能力匹配、优先级、延迟、电量、负载和链路健康度。

### 3.6 路径规划与风险评估

路径规划基于 `AdaptiveRoutePlanner` 的 A* 动态边权搜索，候选路径输出包含：

- `routeId`
- `path`
- `distanceKm`
- `congestion`
- `risk`
- `roadCondition`
- `emergencyLaneAvailable`
- `communicationCoverage`
- `cost`
- `recommended`
- `reason`

系统同时返回推荐理由、风险说明和不推荐路径原因。

### 3.7 DDS 通信模拟

DDS 模拟链路支持：

- 发布事件 `PUBLISH`
- 订阅回调 `SUBSCRIBE`
- 可靠重试 `RETRY`
- 最佳努力丢包 `DROPPED`
- 降级事件 `DEGRADE`

每条日志包含：

- `timestamp`
- `missionId`
- `phase`
- `topic`
- `status`
- `reason`
- `retryCount`

## 4. 新增和增强 API

### `/api/agent/plan`

输入自然语言任务，返回完整协同计划。新增返回：

- `platformPlan`
- `structuredDsl`
- `ddsSimulation`
- `communicationLogs`
- `riskWarnings`
- `fallbackStrategies`

### `/api/agent/devices`

返回平台级设备状态，包括能力、电量、负载、链路质量、位置、状态和支持 Topic。

### `/api/agent/topics`

返回 DDS Topic、IDL 类型、方向和业务说明。

### `/api/agent/logs`

返回最近的 DDS 发布、订阅、重试、失败和降级日志。

### `/api/agent/simulate`

模拟任务执行过程，返回 DDS 模拟事件、通信日志、风险提示和降级策略。

### `/api/agent/health`

返回平台模块健康状态，包括意图解析、DSL 生成、DDS 模拟、路径规划和任务调度。

## 5. 前端增强

工作台新增“完整协同计划”展示区，包含：

- 结构化 DSL 卡片；
- DDS Topic / QoS 策略；
- 设备分工；
- DDS 执行日志；
- 风险提示与降级策略；
- 路径算法和任务调度摘要。

页面仍保留原有地图、协同闭环、DSL/Java 产物、Topic 表格等功能。

## 6. 异常处理与稳定性

系统已补充以下兜底逻辑：

- 输入为空：使用默认任务意图；
- 起点/终点缺失：使用默认起点和医院目的地，并返回提示；
- 任务无法识别：回退为多设备联合巡逻；
- 设备或任务为空：调度器返回空调度结果；
- 路径不可达或算法异常：回退主路候选；
- DDS 消息失败：可靠 Topic 自动重试，最佳努力 Topic 记录丢包并等待下一周期；
- 链路质量差：返回备用链路和降级策略；
- 返回数据为空：接口返回稳定结构和解释信息。

```powershell
.\runtime\jdk\bin\java.exe -cp "build-classes;generated-src;source;lib/*" server.FrontendApiServer 8080
```

```powershell
cd frontend
npm run build
```

```powershell

```

## 8. 后续优化方向

- 接入真实 DDS DomainParticipant、DataWriter、DataReader，而不是仅做 API 层模拟。
- 将结构化 DSL 进一步落盘为标准 DSL 文件，并与 ANTLR 解析器双向校验。
- 将 IDL 绑定扩展为真实 TypeSupport 自动匹配和序列化校验。
- 接入真实地图路网边、交通流和道路事件，实现更完整的城市级路径搜索。
- 为任务调度增加匈牙利算法或整数规划版本，在大规模设备任务场景中对比贪心调度效果。
- 为前端增加任务回放、日志筛选、DDS Topic 拓扑图和风险热力图。
# 2026-05-11 系统性完善补充

本次完善围绕项目真实不足进行增强，没有改变后端原生 `HttpServer` 和前端 React/Vite 的免安装结构。项目仍定位为实验型无人系统意图协同平台原型，不是生产级真实控制系统。

## 2026-05-11 第二轮功能增强

第二轮增强面向实验报告和答辩展示，新增典型场景库、故障注入、风险评估、Topic 拓扑、任务历史、平台 Dashboard 和 Markdown 报告导出。场景库内置医疗应急转运、无人机事故巡检、多设备联合巡逻、物资配送、极端天气道路风险监测和跨区域交通态势同步 6 类任务；故障注入支持设备离线、低电量、链路退化、DDS 发布失败、高拥堵、路径阻断和传感器不可用；风险评估引擎输出风险分数、等级、风险因子、缓解措施和 fallback 判断；Topic 拓扑将设备、Topic 和服务模块转化为节点，将发布、订阅、重试、降级关系转化为边；任务历史服务保存最近任务计划和执行摘要；Dashboard 汇总任务、设备、风险、DDS 模式、故障和重试指标；报告导出接口返回 Markdown 文本，便于实验材料整理。

## 1. 统一任务模型与结构化 DSL

新增 `source/agent/MissionDslModel.java`，作为平台内部统一任务模型。该模型覆盖 `missionId`、`originalText`、`taskType`、`priority`、`source`、`target`、`devices`、`constraints`、`qosRequirement`、`requiredTopics`、`publishTopics`、`subscribeTopics`、`idlType`、`routeRequirement`、`collaborationRequirement`、`expectedOutput` 和 `fallbackPolicy` 等字段。

`/api/agent/plan` 仍保留 `dslPreview`、`platformPlan`、`structuredDsl`、`collaboration` 等兼容字段，但 `structuredDsl` 已改为更完整的 schema，便于后续 DSL/IDL/DDS 统一映射。

## 2. DDS 通信统一抽象与 fallback

新增 `source/agent/DdsCommunicationService.java`，将 DDS 发布、订阅、通信日志和模拟交换统一到一个服务层。服务会探测 DDS 管理类，不能使用真实 DDS runtime 时自动回退到 `SIMULATED_DDS` 或 `FALLBACK_SIMULATION`，因此免安装环境仍可运行。

QoS 不再只是文本，而是结构化对象，包含可靠性、持久性、deadline、延迟预算、历史深度、优先级、重试次数和降级策略。`/api/agent/plan`、`/api/agent/topics` 和 `/api/agent/simulate` 均会返回 DDS runtimeMode、通信过程、QoS 理由和重试/降级信息。

## 3. 设备注册、心跳与状态更新

新增 `source/agent/DeviceRegistry.java`，将原静态设备 catalog 增强为内存级设备注册中心。设备状态包含设备类型、能力、支持 Topic、电量、负载、链路质量、位置、状态、最近心跳、故障原因和当前任务。

`/api/device/action` 的 `bind`、`unbind`、`reconnect`、`inspect/check` 会真实修改注册中心状态。`DynamicTaskScheduler` 的设备输入已改为读取 `DeviceRegistry`，因此离线、低电量、链路差或高负载设备会影响后续任务调度结果。

## 4. 可回放任务执行时间线

新增 `source/agent/MissionExecutionService.java` 和 `ExecutionTimelineEvent.java`。`/api/agent/execute` 不再只返回 accepted，而是创建 `runId`、`timeline` 和 `timelineSummary`。`/api/agent/simulate` 返回完整 `executionTimeline`。

时间线覆盖 `INTENT_PARSED`、`DSL_GENERATED`、`IDL_BOUND`、`QOS_SELECTED`、`ROUTE_PLANNED`、`TASK_SCHEDULED`、`DDS_PUBLISH`、`DDS_SUBSCRIBE`、`DEVICE_ACK`、`RISK_CHECK`、`FALLBACK_TRIGGERED` 和 `COMPLETED` 等阶段，便于前端回放和实验报告分析。

## 5. 前端平台化展示

增强 `WorkbenchPage.tsx`、`DevicesPage.tsx` 和 `TopicsPage.tsx`：

- 工作台展示统一 structuredDsl、DDS runtimeMode、Topic 发布/订阅链路、QoS 理由、候选路径、设备评分、备选设备、风险提示、fallback 策略和执行时间线。
- 设备页展示注册中心状态，包括在线状态、电量、负载、链路质量、能力、最近心跳和当前任务，并支持设备动作后刷新。
- Topic 页展示 Topic 目录、方向、IDL 类型、默认 QoS、发布者、订阅者和最近通信日志。
