# 算法能力补充说明

## 现有算法检查结论

当前项目已经存在部分有效算法和性能机制：

- `nlu.NLUCacheManager`：基于 `LinkedHashMap(accessOrder=true)` 的 LRU 缓存，适合自然语言解析、DSL 生成和地理编码结果复用。查询/写入均摊复杂度为 `O(1)`，空间复杂度为 `O(N)`。
- `integration.VirtualDDSScenarioDemo`：使用 `ScheduledExecutorService`、`ConcurrentHashMap`、`CopyOnWriteArrayList` 模拟 DDS 并发发布订阅、QoS TTL、丢包和可靠重试，适合实时通信演示。
- `agent.DataMatchingEngine`：使用集合交集和字段匹配完成供需主题匹配，复杂度约为 `O(P + R)` 或 `O(F*K)`，适合小规模设备能力匹配。
- `agent.CollaborativeDataFusionEngine`：按数据源可信度、时效性和场景一致性做加权融合，能支撑多源态势判断。
- `protocol.MultiLinkStrategyEngine`：已有链路主备策略，但偏规则表驱动，适合工程策略解释，不是严格优化算法。

不足之处：

- 路线选择主要依赖规则判断和风险最小值比较，无法表达路网拓扑、路段动态代价和多候选路径搜索。
- 多设备协同任务缺少显式调度算法，无法根据设备能力、延迟、电量、负载和链路健康度做可解释分配。
- 真实地图路网、实时交通流和全局最优多目标规划不适合在当前免安装演示工程中直接强接入，后续可通过地图 API 路网边、DDS 实时状态和 MILP/匈牙利算法扩展。

## 新增算法

### `agent.AdaptiveRoutePlanner`

用途：将主路、高架绕行、学校慢行、应急绿波等候选路线抽象为有向图，并使用 A* 搜索选择动态最小代价路径。

动态边权考虑：

- 拥堵程度
- 乘客是否紧急
- 是否安全优先
- 路面附着系数
- 应急车道净空
- 路段基础时间和基础风险

复杂度：

- 时间复杂度：`O((V + E) log V)`
- 空间复杂度：`O(V + E)`

应用位置：

- `agent.CollaborationDecisionEngine.evaluate`
- 返回字段：`collaboration.routePlan`
- 最终决策字段：`finalDecision.routeAlgorithm`、`finalDecision.routePath`、`finalDecision.routeCost`

### `agent.DynamicTaskScheduler`

用途：为无人车、无人机、RSU、合规广域态势链路分配协同任务。

评分因素：

- 设备能力是否覆盖任务需求
- 任务优先级
- 链路延迟
- 电量
- 当前负载
- 链路健康度

算法：

- 构建任务-设备候选边
- 使用最大评分优先队列做动态权重贪心任务调度
- 适合实时演示和小中规模自治协同
- 该实现不是严格的二分图最大匹配或匈牙利算法，目标是快速、稳定、可解释地给出实时协同分工

复杂度：

- 时间复杂度：`O(TD log(TD))`
- 空间复杂度：`O(TD)`

应用位置：

- `agent.CollaborationDecisionEngine.evaluate`
- 返回字段：`collaboration.taskSchedule`

## 为什么选择这些算法

A*/Dijkstra 适合本项目的路径搜索问题。无人车路线决策天然可以抽象为图搜索：节点表示关键路段、路口或事件点，边表示可通行路段。Dijkstra 能在非负边权图中保证最短代价路径；A* 在加入空间启发式后能减少搜索范围，更适合实时路线重规划。本项目当前没有强依赖真实地图路网，因此采用可离线运行的抽象路网 A*，同时保留退化为 Dijkstra 的解释空间，便于后续接入真实道路拓扑。

动态权重贪心任务调度适合实时多设备协同分配。车、无人机、RSU、广域态势链路的任务数量较少，但状态变化快，调度结果需要可解释、低延迟、易回退。相比匈牙利算法或整数规划，动态权重贪心可以直接融合能力匹配、任务优先级、链路延迟、电量、负载和链路健康度，在 `O(TD log(TD))` 内稳定给出足够好的分配结果，符合车端自治协同演示的实时性要求。

## 不直接实现的后续优化

- 全量真实路网最短路：需要地图 API 返回可用路段拓扑、道路等级、转向限制和实时路况；当前项目已有高德 API 适配，但演示链路不保证联网和完整路网边，因此本次先实现可离线运行的路网抽象版 A*。
- 全局最优多设备分配：匈牙利算法或整数规划适合任务和设备规模较大、且要求全局最优的场景；当前任务数少、实时解释优先，动态权重贪心更稳妥。后续可在 `DynamicTaskScheduler` 中增加 `scheduleOptimal` 方法。
- 分布式一致性协同：Raft/Paxos 等共识算法不适合当前车端自治路线建议场景，项目目标是设备建议融合而不是复制状态机一致性。
