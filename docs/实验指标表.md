# 实验指标表

本指标表用于支撑“自然语言意图 -> DSL -> IDL/DDS -> 多设备建议 -> 路线融合决策”的竞赛展示和论文实验。指标分为通信层、协同层、决策层和系统层四类。

## 1. 通信层指标

| 指标 | 记号 | 计算方式 | 数据来源 | 说明 |
| --- | --- | --- | --- | --- |
| DDS 投递率 | Delivery Ratio | `delivered / published` | `VirtualDDSScenarioDemo`, `RouteFusionExperiment` | 衡量 Topic 消息是否能在虚拟无线环境中到达订阅者。 |
| 丢包率 | Drop Ratio | `dropped / published` | `VirtualDDSScenarioDemo` | 衡量通信环境扰动对协同闭环的影响。 |
| 重试次数 | Retry Count | reliable QoS 触发的重传次数 | `VirtualDDSScenarioDemo`, `RouteFusionExperiment` | 反映可靠 QoS 的开销。 |
| 过期消息数 | Stale Count | 到达时间超过 deadline 的消息数 | `RouteFusionExperiment` | 衡量高延迟下建议是否失去决策价值。 |
| 平均投递延迟 | Avg Latency | `sum(latency_ms) / delivered` | `RouteFusionExperiment` | 衡量 QoS 和链路状态对实时性的影响。 |

## 2. 协同层指标

| 指标 | 记号 | 计算方式 | 数据来源 | 说明 |
| --- | --- | --- | --- | --- |
| 有效建议到达率 | Advice Arrival Ratio | `delivered_advice / total_advice` | `RouteFusionExperiment` | 衡量无人车、无人机、RSU、广域链路建议是否及时进入融合器。 |
| 设备参与度 | Device Participation | `active_sources / all_sources` | `VirtualDDSScenarioDemo` | 衡量参与协同的设备数量。 |
| 路线一致性 | Route Stability | `agree_with_final_route / delivered_advice` | `RouteFusionExperiment` | 衡量最终路线与设备建议的一致程度。 |
| 建议冲突强度 | Conflict Level | `NONE / MODERATE / HIGH` | 实验配置 | 用于构造不同实验组。 |

## 3. 决策层指标

| 指标 | 记号 | 计算方式 | 数据来源 | 说明 |
| --- | --- | --- | --- | --- |
| 最终路线 | Final Route | 融合器输出的路线 ID | `VirtualDDSScenarioDemo`, `RouteFusionExperiment` | 例如 `route_D_emergency_green_wave`。 |
| 风险评分 | Risk Score | 多源建议按权重融合后的风险值 | `RouteFusionExperiment` | 越低表示路线越安全。 |
| 决策置信度 | Confidence | 按设备置信度、权威度、延迟衰减综合计算 | `RouteFusionExperiment` | 衡量最终路线可信程度。 |
| 重规划触发 | Replan Triggered | 是否从原路线切换到新路线 | `VirtualDDSScenarioDemo` | 事故、拥堵、低摩擦等事件触发。 |
| 风险降低率 | Risk Reduction | `(baseline_risk - fused_risk) / baseline_risk` | 对比实验 | 用于论文中说明协同收益。 |

## 4. 系统层指标

| 指标 | 记号 | 计算方式 | 数据来源 | 说明 |
| --- | --- | --- | --- | --- |
| 端到端闭环时间 | E2E Latency | 乘客意图发布到最终决策输出的时间 | 后续可由日志时间戳计算 | 衡量自然语言意图进入无人设备协同闭环的效率。 |
| DDS/IDL 覆盖率 | Interface Coverage | `defined_idl_types / required_message_types` | `idl/urban_intent_collaboration.idl` | 衡量核心消息是否已有接口定义。 |
| 自主协同比例 | Autonomy Ratio | `vehicle_self_decision_cases / total_cases` | 场景日志 | 说明系统不是控制中心派单。 |
| 可复现实验数 | Reproducible Cases | 自动实验组合数量 | `RouteFusionExperiment` | 当前为 `2 * 3 * 3 = 18` 组。 |

## 5. 当前可展示结论

从已实现的 `RouteFusionExperiment` 初步结果看：

- 在低延迟场景下，`RELIABLE` 与 `BEST_EFFORT` 都能保持较高建议到达率。
- 在高延迟、高冲突场景下，`BEST_EFFORT` 更容易丢失关键建议，可能导致最终路线退化为高风险路线。
- `RELIABLE` QoS 会带来重试和延迟成本，但能在复杂冲突场景中保住更多关键建议，从而降低最终路线风险。
