# 对比实验设计

## 1. 实验目的

验证在未来无人智能交通协同场景中，不同 DDS QoS、不同网络延迟、不同设备建议冲突程度，会如何影响最终路线融合结果。

核心问题：

1. 可靠 QoS 是否能降低关键设备建议丢失导致的错误路线选择？
2. 高延迟是否会让设备建议过期，从而降低路线融合质量？
3. 当无人车、无人机、RSU、广域链路给出冲突建议时，融合算法是否仍能选择低风险路线？

## 2. 实验变量

| 自变量 | 取值 | 含义 |
| --- | --- | --- |
| QoS 模式 | `RELIABLE`, `BEST_EFFORT` | 模拟可靠投递与尽力而为投递。 |
| 延迟等级 | `LOW`, `MEDIUM`, `HIGH` | 模拟低延迟城市专网、中等拥塞网络、高延迟弱链路。 |
| 建议冲突 | `NONE`, `MODERATE`, `HIGH` | 模拟设备建议一致、部分冲突、高度冲突。 |

当前组合数：

```text
2 QoS * 3 latency * 3 conflict = 18 cases
```

## 3. 因变量与评价指标

| 因变量 | 指标 | 解释 |
| --- | --- | --- |
| 通信可靠性 | `Delivered`, `Dropped`, `Retry`, `Stale` | 判断建议是否成功、及时进入融合器。 |
| 决策质量 | `Final Route`, `Risk`, `Confidence` | 判断最终路线是否安全可信。 |
| 协同一致性 | `Route Stability` | 判断最终路线与多少设备建议一致。 |
| 实时性 | `Avg Latency` | 判断通信和 QoS 是否满足协同决策时限。 |

## 5. 融合逻辑

每条设备建议包含：

- `source`：建议来源，如主车、邻车、无人机、RSU、合规广域链路。
- `route`：候选路线。
- `risk`：该路线风险评分。
- `confidence`：该设备对建议的置信度。
- `latency`：建议到达延迟。

融合器综合以下因素：

- 设备权威度：RSU、无人机、主车、广域链路、邻车权重不同。
- 建议新鲜度：延迟越高，建议权重越低。
- 风险评分：风险越低，越容易被选择。
- 冲突惩罚：冲突越强，整体置信度越低。

最终输出：

- `final_route`
- `final_risk_score`
- `confidence`
- `route_stability`

## 6. 当前初步结论

当前实验中最有代表性的对比：

| 场景 | 有效建议 | 最终路线 | 风险 |
| --- | ---: | --- | ---: |
| `RELIABLE + HIGH latency + HIGH conflict` | `3/5` | `route_D_emergency_green_wave` | `0.250` |
| `BEST_EFFORT + HIGH latency + HIGH conflict` | `1/5` | `route_A_main_road` | `0.520` |

解释：

- 在高延迟、高冲突情况下，`BEST_EFFORT` 丢失了更多关键建议，融合器只能基于少量信息做出保守甚至退化的路线选择。
- `RELIABLE` 虽然产生了重试和部分过期消息，但保留了更多来自 RSU、无人机、广域链路的关键建议，因此能选择风险更低的路线。

## 7. 论文写法建议

论文中可以将实验章节写成：

1. 场景设定：乘客自然语言意图触发无人车、无人机、RSU、邻车协同。
2. 变量设计：QoS、延迟、建议冲突。
3. 指标体系：投递率、过期消息、路线稳定性、风险评分、置信度。
4. 结果分析：可靠 QoS 与 best-effort 在复杂交通场景下的差异。
5. 结论：可靠 QoS 更适合关键路线决策消息，best-effort 更适合高频传感器流。

## 8. 下一步可扩展实验

- 加入更多设备数量：从 5 个建议源扩展到 10 个、20 个。
- 加入真实 ROS2/DDS：对比虚拟 DDS 与真实 DDS 的延迟差异。
- 加入 SUMO/CARLA：将路线风险与真实交通仿真联动。
- 加入自然语言扰动：测试不同乘客表达对 DSL 生成稳定性的影响。
- 加入消融实验：只用主车、主车+无人机、主车+无人机+RSU、全设备协同。
